# Единый реестр заказов и выдачи

## Источник правды

Центральный Neon у `oper-stack.com` хранит пять отдельных фактов: событие провайдера,
заказ, право на продукт, задачу выдачи и письмо. Google Sheets остаётся удобным журналом
лидов, но больше не решает, имеет ли человек право получить товар и можно ли ему продавать
эту же ступень.

Таблицы создаются добавочно при первом обращении. Существующие `checks`, `sites`, `visits`,
`scores` и `webhook_once` не меняются.

- `commerce_provider_events` — события Whop по их настоящему webhook id.
- `commerce_orders` — одна строка на коммерческий заказ или запрос счёта.
- `commerce_entitlements` — что уже куплено. Более высокая ступень добавляет включённые нижние.
- `commerce_fulfilment_jobs` — выдача продукта с состояниями `pending`, `processing`, `accepted`, `failed`.
- `commerce_messages` — логический вид письма, канал и id сообщения у провайдера.
- `commerce_contact_preferences` — отписки, жалобы и постоянные отказы доставки.

## Повторы и ошибки

Webhook сначала резервирует задачу, потом отправляет письмо. Одновременно её может взять только
один запрос. Повтор Whop во время обработки получает успешный ответ без второй выдачи. Ошибка
почты переводит задачу в `failed` и возвращает Whop код 503, поэтому следующий повтор продолжает
ту же задачу. Resend получает постоянный `Idempotency-Key` задачи.

Сетевой обрыв после запроса к Resend считается неоднозначным: код не переключается в этот момент
на Google, потому что первое письмо уже могло быть принято. Явный отказ Resend до приёма можно
безопасно отправить через Google.

## Цепочка продаж

Перед каждым письмом 2–6 worker вызывает подписанный `/api/commerce/` и проверяет конкретные
предложения внутри письма. Купленный аудит также закрывает предложения $9 и $29. Агентский тариф
закрывает включённые отчёты. Отписка, complaint и hard bounce закрывают маркетинговые письма,
но не письма с уже оплаченным товаром.

## Переменные

На EN/Vercel:

- `DATABASE_URL` — существующий Neon.
- `OPERSTACK_LEDGER_SECRET` — случайная строка не короче 32 байт.
- `RESEND_WEBHOOK_SECRET` — signing secret созданного webhook Resend.
- `WHOP_COURSE_IDS` и остальные `WHOP_*_IDS` — актуальные product/plan ids.
- `OPERSTACK_DASHBOARD_USER` и `OPERSTACK_DASHBOARD_PASSWORD` — вход на `/ops/orders/`.

На RU/Vercel:

- `OPERSTACK_LEDGER_URL=https://oper-stack.com/api/commerce/`
- тот же `OPERSTACK_LEDGER_SECRET`.

В GitHub Actions репозитория `ops-notify`:

- secret `OPERSTACK_LEDGER_SECRET`;
- variable `OPERSTACK_LEDGER_URL=https://oper-stack.com/api/commerce/`.

## Порядок включения

1. Развернуть EN. Проверить `GET /api/whop-webhook/` и что новый `/api/commerce/` отвечает 401 без подписи.
2. Добавить webhook Resend на `https://oper-stack.com/api/resend-webhook/` для sent, delivered,
   delayed, bounced, complained и failed; сохранить signing secret в Vercel и снова развернуть EN.
3. В Whop направить события оплаты/членства на существующий webhook и сделать по одной тестовой
   покупке каждого вида. Вторая доставка того же события недопустима.
4. Добавить общий secret и URL в `ops-notify`, запустить `sequence` с `dry=true`, затем обычный
   запуск на собственном тестовом адресе.
5. Развернуть RU с тем же secret. Запрос счёта должен появиться в `commerce_orders` со статусом
   `pending` до отправки письма.

## Проверка

Для каждой покупки должны существовать: один `commerce_orders`, нужные права в
`commerce_entitlements`, одна принятая задача и одно письмо. Для курса письмо не создаётся:
доступ выдаёт Whop Courses, а задача `whop-course-access` фиксирует этот факт.

Если выдача зависла в `processing`, подождать 15 минут и повторить то же событие Whop. Если письмо
имеет `accepted`, но нет `delivered`, смотреть событие Resend по `provider_message_id`.

Закрытый экран `/ops/orders/` показывает последние сто заказов, сумму оплаченных заказов по
валютам и состояние задач/писем. Браузер сам показывает окно Basic Auth; адрес не содержит пароль,
страница закрыта от индексации и не кэшируется.
