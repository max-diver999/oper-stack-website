# Как исполнить заказ на отчёт за 9 и 29 долларов

Покупатель платит, вводит адрес сайта, и на почту очереди падает письмо с темой `Report request: <хост> (9 USD)`. Ниже что с ним делать. Занимает несколько минут, из них машина работает меньше минуты.

С 12 сентября 2026 покупателю уходит **два файла**, а не один. Список задач это теперь главный товар, замер идёт приложением. Если отправить только PDF, покупатель не получит то, за что заплатил.

## Что в письме очереди

```
Site: https://example.com
Buyer: someone@example.com
Tier: 9 USD
Language: en
```

`Tier: 29 USD` означает, что в письме ещё строка `Rivals:` с адресами до трёх конкурентов.

## Три команды

```bash
cd ~/Desktop/Cursor_ed/OperStack/audit-generator

# 1. Прогон сайта. Двадцать страниц, язык из письма
node bin/audit.mjs collect https://example.com --pages 20 --lang en --out /tmp/example.json

# 2. Список задач. Это главный файл
node bin/audit.mjs prompts /tmp/example.json --lang en --out /tmp/example-tasks.md

# 3. Замер в виде PDF
node bin/audit.mjs render /tmp/example.json --pdf --out /tmp/example-report.html
```

Прогон с рендером в браузере занимает около минуты на сайт. Флаг `--no-rendered` его выключает, но для платного отчёта выключать нельзя: проверка «сколько текста пропадает без скриптов» именно там и делается.

## Что отправить покупателю

Письмо с двумя вложениями:

1. **`<хост>-tasks.md`** или его же PDF: список задач. В теле письма одна фраза о том, что начинать надо с первой задачи и делать по одной.
2. **`<хост>-report.pdf`**: замер.

Порядок важен. Задачи первыми, замер вторым.

## Для тарифа 29

Дополнительно прогнать каждого конкурента из строки `Rivals:` той же командой `collect` и приложить сравнение.

Четыре еженедельных среза отправляет **очередь сама**: `report-run.mjs` в момент отправки отчёта записывает покупателя в лист «Наблюдение» таблицы (с баллами на этот день), а задание `watch` в `oper-stack/ops-notify` раз в день перемеряет тех, у кого подошёл срок (7, 14, 21, 28 дней), тем же кодом, что страница проверки, и шлёт письмо «было, стало, разница». Руками ничего делать не нужно.

Если в Telegram пришла тревога «запись на еженедельные срезы не удалась», записать руками из `ops-notify`:

```
node watch-run.mjs --register --kind=rivals-weekly --email=<почта> --url=<сайт> --lang=<ru|en> --rivals=<a.com,b.com>
```

## Перепроверки для аудита и Fix

У аудита (149) и пакета Fix автоматической выдачи нет, поэтому запись на перепроверку делается **руками при выдаче**, той же командой. Без этой строки письма не будет, а на странице оно обещано.

```
node watch-run.mjs --register --kind=audit-90 --email=<почта> --url=<сайт> --lang=<ru|en>    # через 90 дней после аудита
node watch-run.mjs --register --kind=fix-30   --email=<почта> --url=<сайт> --lang=<ru|en>    # через 30 дней после Fix
```

Ключи таблицы есть только в Actions, поэтому проще запустить задание `watch` с входом `register` (JSON с теми же полями) на странице Actions репозитория `ops-notify`.

## Чего делать нельзя

- Отправлять только PDF без списка задач. Это и есть товар.
- Ставить в отчёт цифру, которой нет в прогоне. Если область не измерена, в отчёте так и написано «не измерено», и это правильно.
- Обещать сроки, кроме тех, что уже написаны на странице: «обычно в течение часа».

## Если прогон падает

Сайт мог закрыться от автоматических читателей или лежать. Написать покупателю с адреса `info@oper-stack.com`, объяснить одной фразой и предложить вернуть деньги. Возврат по Site Kit семь дней, по отчёту решение за Максимом.
